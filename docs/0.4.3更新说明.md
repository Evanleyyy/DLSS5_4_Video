# 0.4.3：同一模型调参复用

模型会话现在由应用持有。一次图片、视频或批量任务完成后，不再立即卸载当前模型；继续修改同一模型的普通参数并确认处理时，直接应用新参数。

## 使用行为

- 滑块、颜色、遮罩和参数预设仍然只修改待确认选项，点击“确认参数并开始处理”后才计算。
- DLSS 的强度、风格、局部色调、结构、降噪、混合权重等普通参数变化，不重新加载运行库。两层各自复用；关闭第二层会释放第二层。
- 同尺寸的图片、视频和批量任务可以继续使用当前 DLSS 会话；每个独立素材开始时重置时序历史，避免上一素材影响下一素材。
- PiSA、SeedVR2、VOSR 同模型的连续任务保留工作进程与模型对象，更新种子、分块、颜色及引擎专用参数。SeedVR2 保持 CPU 卸载策略，模型可能分布于内存和显存，并非始终全部占用显存。
- PiSA 保留首次合并后的语义权重，在分块和任务间直接恢复相同缓冲区，避免上游半精度重新相加与首次合并结果不一致；这不会从磁盘重新加载模型。
- 切换实际模型版本、超分引擎或权重目录后，在确认执行时释放旧模型；退出软件释放全部持有的模型。渲染进程出错后丢弃会话，下一次确认重新加载。

## 需要重新初始化的情况

原生 DLSS 的预设编号（1、2、3）与输入缓冲尺寸属于创建参数，修改后需要重建隔离会话。自动选择与手动选择如果指向同一个实际版本，则不会仅因选项名称不同而重建。

整体权重降到零会释放已加载的 DLSS 层，之后重新启用需要加载。首次生成新的深度或光流通道时，会先释放当前渲染模型来腾出显存；已有有效引导缓存则可复用。模型自检和显式清理超分缓存也会释放相应会话。

模型驻留会使任务完成后的内存或显存占用高于旧版，这是避免反复加载的预期行为。

## 验证

测试环境：RTX 4090 Laptop、驱动 596.36。三个 DLSS 版本均以真实确认按钮连续改变参数，验证进程编号不变、输出像素改变、未确认不计算。另检查双层分别复用、关层释放、原生预设重建、连续视频复用及退出无残留进程。

128×128 测试图的 DLSS 首次处理约 1.6～1.8 秒，复用后约 0.08～0.14 秒。该结果主要反映短任务初始化开销，不代表大图或长视频的相同比例提升；RTX 30 系尚未实机验证。
