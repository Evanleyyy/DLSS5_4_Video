# 导出缓存与后台任务修复（0.3.5）

## 根本原因

旧版超分子进程可能在主程序退出后继续运行。旧 SeedVR2 任务与后续 DLSS 任务直接写入同一个视频缓存目录，导致原尺寸结果被两倍尺寸结果覆盖。缓存的“已完成”标记未随覆盖失效，导出才发现帧尺寸不一致。

本次现场证据：缓存 `000413.png` 为 1080×1920，`000414.png` 为 2160×3840；对应原视频帧都是 1080×1920。旧任务的主进程已经不存在，子进程仍持续输出；新缓存标记完成后又有帧被改写。排查期间混入的两倍尺寸帧由 135 张增至 144 张。

经用户同意，已停止这一残留任务，保留原素材、现有帧和导出文件。已覆盖的帧内容需要重新生成。

## 修复后的行为

- Windows 将超分子进程绑定到主程序的进程任务组，主程序异常退出时也会结束子进程。工作进程在正常运行与暂停期间都会检查主程序是否存在。
- 视频超分写入安装目录 `data/sr-cache` 下的独立任务目录。全部帧完成、数量和尺寸校验通过后，由持有视频缓存锁的主程序发布结果。
- 支持临时目录和视频缓存位于不同磁盘；单帧发布使用目标磁盘上的临时文件替换，避免读取未写完的图片。
- 导出前检查整组处理结果的文件与尺寸。发现混合、缺失或无法识别的帧时，记录具体帧号和尺寸并重新生成，再继续导出。
- 编码时仍保留最终校验，尺寸错误和数量错误分别报告。

## 使用

已有 0.3.0～0.3.4 安装版运行 `DLSS5_Update_0.3.5.exe`，选择原安装目录。模型与参数保持原位。

重新导出受到影响的视频时，程序会检测缓存并重新处理。完整重新生成仍需要正常处理时间，暂停／继续生成仍可使用。已经混入其他模型效果的图片不能通过简单缩放恢复成原来的 DLSS 结果。

## 验证

- 回归复现：正常运行的工作进程未检查主程序退出、子进程直接覆盖缓存、混合尺寸被标记为完成，旧实现均失败。
- 修复后通过任务回收、阶段隔离、发布前全帧校验、跨磁盘发布及混合缓存重新生成测试。
- 真实 Windows 测试直接结束专门创建的任务宿主，确认其子进程自动结束，无须执行宿主的退出清理代码。
- 安装版入口 `--verify-export-cache` 使用真实超分工作进程和三帧短视频，主动构造混合缓存，检查自动重新生成以及原图、两倍尺寸结果分别成功导出。此测试整体权重为零，用于验证任务和文件流程，不测模型画质。
