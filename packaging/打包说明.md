# 完整单文件 EXE

本方案将修复后的应用、Python、PyTorch CUDA 运行库、深度/光流模型、Tk 图形界面和 FFmpeg 打包为 `output/DLSS5_Standalone.exe`。使用 PyInstaller 生成内部应用，再以无损 7z 压缩和独立启动器封装为单个 EXE。

## 重新打包

先从 [7-Zip 官方下载页](https://www.7-zip.org/download.html)取得 26.03 的 Extra 便携包，解压到 `build/7zip`，使 `build/7zip/x64/7za.exe` 存在。然后在项目目录的 PowerShell 中执行：

```powershell
uv --cache-dir downloads\uv-cache pip install --python .venv\Scripts\python.exe -r packaging\requirements-build.txt
.\打包EXE.ps1
```

构建产物放在 `output`，中间文件放在 `build`。打包配置不使用 UPX。启动器使用 Windows 自带的 .NET Framework，运行不需要管理员权限。

## 独立运行验证

```powershell
.venv\Scripts\python.exe packaging\verify_exe.py
```

验证器将 EXE 单独复制到 `tests/exe-isolation`，移除测试子进程中的 Python 环境变量，将 PATH 限制为 Windows 系统目录，再执行 EXE 内置自检。

检查内容包括：依赖及模型全部从单文件解压目录读取、真实 DLSS、深度模型、光流模型、联合引导、带音轨导出、Tk 界面和奇数尺寸图片处理。结果保存在 `logs/exe-verification/verification.json`。

界面验证还覆盖五种窗口尺寸、图片滚轮缩放与拖动、画笔和橡皮、矩形选区、撤销/重做、边缘羽化，以及实际保存的局部处理 PNG。源码回归测试使用 `python -m unittest discover -s tests -p "test_*.py"`，界面交互测试使用 `python tests/gui_editor_smoke.py`。

多通道导出验证使用 `python tests/gui_export_smoke.py`，实际执行 GUI 导出命令，检查单图多通道 PNG、静态 MP4、视频当前帧、全部帧 PNG 序列和带音轨的多通道视频。独立 EXE 自检也包含这些检查，结果记录在 `stages.multi_channel_export`。

由于已确认本机工具沙箱会影响原生 DLL 的释放操作，GPU 验证需要在正常本机进程中运行。

## 运行行为

- 单文件启动器在首次运行时将内置资源解压到 `%LOCALAPPDATA%/DLSS5Standalone/runtime`，显示准备进度；完成后保留缓存，以后直接启动。无需安装 Python、Torch、FFmpeg 或手动复制模型。
- 启动器校验内置压缩包的 SHA256，并由解压器校验压缩数据。完整性校验不等于第三方代码签名认证。
- 仍需 Windows 64 位及支持当前原生运行库的 NVIDIA 显卡、驱动。本机测试硬件为 RTX 4090 Laptop。
- 普通运行日志保存到 `%LOCALAPPDATA%\DLSS5Standalone\logs`。
- EXE 可以单独复制；首次展开需要系统盘有足够空间，建议保留 15 GB 空闲。
- 打包不改变此前审计结论：原发布包宿主 DLL 没有源码，NVIDIA DLL 的签名哈希校验异常，无法进行完整二进制安全保证。
