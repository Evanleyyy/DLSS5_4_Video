# 0.3.6 安装包

运行根目录 `打包安装包.ps1`。需要先准备 `runtime/python`、`runtime/sr-packages`、`runtime/pisa-packages`、`runtime/sr-engines`、`runtime/sr-models` 与 `build/inno/ISCC.exe`。

`sr-assets-manifest.json` 固定三套代码提交和全部模型文件的 SHA-256。`tools/download_sr_assets.py` 根据此清单下载与校验权重；代理只读取调用环境中的 `HTTPS_PROXY`。两组推理依赖分别锁定在 `sr-packages.lock.txt` 与 `pisa-packages.lock.txt`。安装用真正可搬迁的 Python 目录与独立包目录，不复制虚拟环境的绝对路径配置。

安装脚本为 `DLSS5_Installer.iss`，应用版本 `0.3.6`。默认构建完整包 `output/DLSS5_Setup_0.3.6.exe` 及同名数据分卷，需放在一起。安装器按组件安装模型，卸载默认保留模型与用户数据。

本次使用 `打包安装包.ps1 -UpdateOnly` 构建 `output/DLSS5_Update_0.3.6.exe`，只更新包含 Python 应用代码的主程序、超分工作脚本与说明，复用 0.3.0 的运行库与模型，也可直接升级 0.3.1～0.3.5。更新安装器保留同一 AppId 和卸载登记，拒绝在缺少基础运行文件的空目录安装。只有依赖不变时才能使用此方式；依赖升级应改发完整包。构建脚本同时生成 SHA-256 校验清单。

0.3.6 预设验收使用 `tests/verify_playback_update.py --target "实际安装目录" --check presets`，覆盖真实预设控件、重启恢复、缓存失效、处理时禁用及宽窄窗口布局。安装验收检查原有超分设置、参数预设与卸载文件均保留；测试预设使用隔离数据目录。源码测试为 `tests/test_parameter_presets.py` 和 `tests/gui_presets_smoke.py`。

更新验收使用 `tests/verify_playback_update.py --target "实际安装目录"`。必须核对桌面快捷方式指向并明确传入目标目录，避免验收更新到另一份安装。安装版 `--verify-playback` 包括 Windows 原生按键消息与锁定键组合测试。

0.3.5 导出缓存修复验收使用 `tests/verify_playback_update.py --target "实际安装目录" --check export-cache`，运行真实工作进程验证缓存发布和自动重建。源码回归为 `tests/test_export_cache_integrity.py`，真实进程退出保护验证为 `tests/worker_lifetime_smoke.py`。

旧单 EXE 打包方法保留如下，仅供旧版回退。

# 旧版完整单文件 EXE

本方案将修复后的应用、Python、PyTorch CUDA 运行库、深度/光流模型、Tk 图形界面和 FFmpeg 打包为 `output/DLSS5_Standalone.exe`。使用 PyInstaller 生成内部应用，再以无损 7z 压缩和独立启动器封装为单个 EXE。

## 重新打包

先从 [7-Zip 官方下载页](https://www.7-zip.org/download.html)取得 26.03 的 Extra 便携包，解压到 `build/7zip`，使 `build/7zip/x64/7za.exe` 存在。然后在项目目录的 PowerShell 中执行：

```powershell
uv --cache-dir downloads\uv-cache pip install --python .venv\Scripts\python.exe -r packaging\requirements-build.txt
.\打包EXE.ps1
```

构建产物放在 `output`，中间文件放在 `build`。打包配置不使用 UPX。启动器使用 Windows 自带的 .NET Framework，运行不需要管理员权限。

## 独立运行验证

```powershell
.venv\Scripts\python.exe packaging\verify_exe.py
```

验证器将 EXE 单独复制到 `tests/exe-isolation`，移除测试子进程中的 Python 环境变量，将 PATH 限制为 Windows 系统目录，再执行 EXE 内置自检。

检查内容包括：依赖及模型全部从单文件解压目录读取、真实 DLSS、深度模型、光流模型、联合引导、带音轨导出、Tk 界面和奇数尺寸图片处理。结果保存在 `logs/exe-verification/verification.json`。

界面验证还覆盖五种窗口尺寸、图片滚轮缩放与拖动、画笔和橡皮、矩形选区、撤销/重做、边缘羽化，以及实际保存的局部处理 PNG。源码回归测试使用 `python -m unittest discover -s tests -p "test_*.py"`，界面交互测试使用 `python tests/gui_editor_smoke.py`。

多通道导出验证使用 `python tests/gui_export_smoke.py`，实际执行 GUI 导出命令，检查单图多通道 PNG、静态 MP4、视频当前帧、全部帧 PNG 序列和带音轨的多通道视频。独立 EXE 自检也包含这些检查，结果记录在 `stages.multi_channel_export`。

双层 DLSS 自检记录在 `stages.two_layer_dlss`，覆盖第二层独立参数、整体权重、局部遮罩 PNG、静态视频、批量图片、第二层视频引导以及连续帧与两次完整模型处理的逐像素比较。第二层通过冻结应用的子进程运行，自检会检查进程释放，并继续检查手动缓存清理。

前后降噪自检记录在 `stages.pre_post_denoise`，使用真实原生 DLSS 分阶段参考验证单层/双层及前后开关组合、各阶段 0%/50%/100% 权重、整体权重、局部遮罩、PNG/静态 MP4/批量图片/视频导出、连续视频预览和缓存失效，并记录 1080p 滤镜耗时。源码运行同一验证器：`python tests/gui_denoise_smoke.py`。

缓存界面验证使用 `python tests/gui_cache_smoke.py`。`python tests/verify_launcher.py` 使用隔离的小型测试资源验证启动器多开、普通退出保留、手动请求后清理及非零退出。独立 EXE 自检通过真实界面登记并取消清理任务，再登记一次；外部验证器确认应用退出后本次解压目录已被删除。该操作只涉及指定验证目录，不会清理用户默认位置的历史缓存。

由于已确认本机工具沙箱会影响原生 DLL 的释放操作，GPU 验证需要在正常本机进程中运行。

## 运行行为

- 单文件启动器在首次运行时将内置资源解压到 `%LOCALAPPDATA%/DLSS5Standalone/runtime`，显示准备进度；完成后保留缓存，以后直接启动。无需安装 Python、Torch、FFmpeg 或手动复制模型。
- “缓存”分类提供手动勾选清理。正在使用的缓存由启动器登记占用，手动请求后等最后一个使用窗口关闭再删除；普通退出不清理。清理采用限定目录内逐个文件删除，拒绝链接和目录联接。
- 启动器校验内置压缩包的 SHA256，并由解压器校验压缩数据。完整性校验不等于第三方代码签名认证。
- 仍需 Windows 64 位及支持当前原生运行库的 NVIDIA 显卡、驱动。本机测试硬件为 RTX 4090 Laptop。
- 普通运行日志保存到 `%LOCALAPPDATA%\DLSS5Standalone\logs`。
- EXE 可以单独复制；首次展开需要系统盘有足够空间，建议保留 15 GB 空闲。
- 打包不改变此前审计结论：原发布包宿主 DLL 没有源码，NVIDIA DLL 的签名哈希校验异常，无法进行完整二进制安全保证。
