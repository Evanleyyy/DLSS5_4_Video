# 0.4.1 统一工作台构建与验证

本地安装包由下列流程生成，产物保存在 `output`；Git 源码不包含安装文件。向第三方分发所含运行库前应核对各组件许可。

## 构建环境

需要准备 `.venv` 构建环境、`runtime/python` 可搬迁 Python、`runtime/sr-packages`、`runtime/pisa-packages`、`runtime/sr-engines`、FFmpeg、DLSS 运行库及 `build/inno/ISCC.exe`。两组推理依赖固定在 `sr-packages.lock.txt` 与 `pisa-packages.lock.txt`。

模型不是构建前提。`sr-assets-manifest.json` 记录引擎提交号、模型大小、SHA-256 和官方来源。构建脚本只检查本地模型，缺失时由安装后的准备窗口或首次使用流程下载。具体规则、官方源限制与模型目录见[模型按需部署说明](../docs/模型按需部署说明.md)。

## 构建命令

```powershell
# 完整安装包：程序、运行库、引擎代码，不含模型权重
.\打包安装包.ps1

# 累计更新：复用已安装的运行库与模型
.\打包安装包.ps1 -UpdateOnly
```

产物都放在 `output`：

| 产物 | 用途 |
|---|---|
| `DLSS5_Setup_0.4.1.exe` 与同名 `.bin` 分卷 | 首次安装；整组文件放在同一目录 |
| `DLSS5_Update_0.4.1.exe` | 已有原项目安装目录更新，保留用户设置和模型 |
| 对应 `_SHA256.txt` | 校验全部安装文件 |

标准安装默认仅安装程序、依赖和三个 DLSS 运行库，不下载其他模型；可另选“安装并准备其他超分和引导模型”，先复用本地文件，再下载缺失文件。静默安装跳过准备窗口。0.4.1 沿用原项目 AppId、程序名称、安装目录及设置路径，原版用户可直接升级并保留模型和参数预设。独立 0.4.0 实验版使用另一 AppId，安装器会拒绝覆盖其已登记目录。更新包拒绝安装到缺少基础运行库的目录；依赖发生变化时必须重新构建完整包。

模型、缓存、本机设置、构建产物由 `.gitignore` 排除。发布只上传程序及运行库安装包，不上传模型。

## 构建目录与磁盘占用

完整安装包与更新包统一复用 `build/installer-app-current`，旧单文件 EXE 流程复用 `build/portable-current`。再次构建会替换对应的暂存产物，不再按时间戳累积整套运行环境。同一项目不要同时运行多个打包命令。

最终安装包仍保存在 `output`；不同版本的发布文件需要另行归档。`build/installer-app-path.txt` 记录当前安装包暂存目录，供本地验证使用。

`runtime/installed-app` 是安装验证脚本生成的测试副本，不是源码运行所需目录。清理后若需重新做安装验证，应先使用安装包重新创建该测试副本。`runtime/sr-models`、`runtime/sr-packages`、`runtime/python`、`.venv` 和源码中的引导模型仍属于运行环境，必须保留。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
```

安装版验证命令格式为 `DLSS5_App.exe --verify-检查项 "隔离日志目录"`。这些自检使用隔离设置和测试素材：

| 检查项 | 内容 |
|---|---|
| `runtimes` | 三个 DLSS 运行库、隔离进程、版本切换、双层渲染、界面保存及带音轨导出；不下载模型 |
| `model-assets` | 官方小文件下载、完整性校验、离线复用、模型补全按钮及安装准备窗口 |
| `presets` | 命名参数预设、重启恢复、处理中禁用与窗口布局 |
| `playback` | 空格播放、控件焦点及 Windows 锁定键组合 |
| `export-cache` | 子进程回收、缓存发布与不一致帧重建 |
| `pause` | 暂停、继续及任务状态 |
| `sr` | 本地超分引擎与导出 |
| `package` | GPU 推理、深度、光流、双层 DLSS、降噪、遮罩与导出综合检查 |

`model-assets` 会下载一个小型官方配置文件，测试文件留在指定日志目录。其它推理检查需先备齐相应模型。源码专项测试及依赖素材要求见根目录 README。

实际升级验证可用 `tests/verify_playback_update.py --target "实际安装目录" --check presets` 或 `--check export-cache`，该脚本会执行更新安装器，必须明确指定需要升级的安装位置。它检查卸载登记与用户设置保护，不应将隔离测试目录误认为用户安装目录。

旧单文件 EXE 启动器、`RuntimeCache.cs` 和相关测试仍用于兼容性验证，不作为新版发布入口；其历史构建说明可从旧版 Git 提交查看。
